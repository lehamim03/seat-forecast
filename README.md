# 좌석예보 (가칭)

> 지도 앱은 **빠른 버스**를, 좌석예보는 **탈 수 있는 버스**를 알려줍니다.

수원 → 서울 광역버스 이용자를 위해 **어느 정류장에서 어떤 버스를 타야 가장 빨리 도착하는지** 추천하는 안드로이드 앱 프로젝트입니다.
출근 시간대 광역버스의 잔여 좌석 데이터를 모아, 버스마다 **탑승 성공 확률**을 예측하고 이를 경로 추천에 반영합니다.

국민대학교 수업 팀 프로젝트입니다.

## 왜 필요한가

- 광역버스(직행좌석형)는 좌석이 차면 정류장에서 더 태우지 않고 지나갑니다.
- 기존 지도 앱은 최단 시간만 계산해서, 출근 시간대에는 **만석이라 탈 수 없는 버스**를 추천하기도 합니다.
- 기존 앱은 '지금' 잔여 좌석만 보여주고, 내가 정류장에 도착할 때의 상황은 알려주지 않습니다.

## 핵심 아이디어

집 주변 **여러 정류장 × 여러 노선** 조합마다 아래 값을 계산해, 가장 빨리 도착하는 조합을 추천합니다.

```
총 소요시간 = 정류장까지 도보 + 기대 대기시간 + 버스 이동시간(서울 첫 정차지까지) + 하차 정류장까지 버스 + 국민대까지 환승
기대 대기시간 = 배차간격 ÷ 2 + 배차간격 × (1 − p) / p      (p = 그 정류장에서의 탑승 성공 확률)
```

- 탑승 확률이 낮은 버스는 "만석이라 다음 차를 기다릴 시간"이 늘어나서 순위가 내려갑니다.
- 몇 분 더 걸어서 **앞 정류장**에서 타면 좌석이 남아 있을 확률이 높아지는데, 이 대가(도보 시간)와 이득(대기 감소)을 함께 비교합니다.

## 실시간 대안 안내: 기다릴까, 걸어갈까, 다른 버스를 탈까?

정류장에서 버스가 만석으로 올 것 같을 때, 지금 이 순간의 버스 위치·잔여 좌석으로 세 가지 선택지를 비교해 추천합니다.

| 선택지 | 내용 | 이럴 때 추천 |
|---|---|---|
| ① 기다리기 | 지금 정류장에서 다음 버스를 기다림 | 첫 차는 만석이지만 바로 뒤 차에 자리가 있을 때 |
| ② 걸어가기 | 전 정류장으로 걸어가 같은 버스를 먼저 탐 | 집 앞에선 만석이지만 앞 정류장에선 자리가 있을 때 |
| ③ 다른 버스 | 다른 노선을 타고 다른 환승 경로로 이동 | 평소 노선이 줄줄이 만석일 때 |

- 다가오는 버스마다 **도착 때 예상 좌석 = 현재 좌석 − 정류장당 좌석 감소 × 남은 정류장 수** 로 탑승 확률을 계산합니다.
- 첫 차부터 차례로 타 보고, 만석이면 다음 차를 기다린다고 보고 **기대 탑승 시각**을 구한 뒤 이동·환승 시간을 더해 비교합니다.
- 걸어가는 동안 지나가 버리는 버스는 제외합니다.

## 요일 · 공휴일 · 지역행사 반영

| 상황 | 반영 방법 |
|---|---|
| 평일 출퇴근 (06:30~09:30, 17:00~20:00) | 기준값 — 좌석이 가장 빨리 줄어듦 |
| 평일 그 외 · 토요일 · 일요일·공휴일 | 좌석 감소 속도 ×0.6 / ×0.5 / ×0.35, 배차간격 ×1.2 / ×1.3 / ×1.5 (config.DAY_FACTORS) |
| 지역행사 (축제 · 공연 · 경기) | 행사장 500m 안 정류장이 내 정류장보다 앞이면 거기서 승객이 몰려 좌석 감소, 서울 쪽이면 주변 정체로 이동시간 증가 |
| 행사 정보에 없는 쏠림 | 다가오는 버스 좌석이 평소의 2배 이상 빨리 줄면 '승객 쏠림'으로 보고 뒤차에도 반영 |

- 공휴일은 한국천문연구원 특일 정보(대체공휴일 포함), 행사는 관광공사 TourAPI와 config.LOCAL_EVENTS(직접 입력)를 씁니다.
- 학습 모델에도 날짜 종류(평일 / 토요일 / 일요일·공휴일)를 입력으로 넣어, 주말 데이터가 쌓이면 차이를 직접 배웁니다.

## 돌발상황 반영: 사고 · 정체 · 시위 · 우회

앞서 서울로 가고 있는 **같은 노선 버스들을 탐침**으로 씁니다 (collect.py 가 1분마다 기록한 최근 20분).
원인이 무엇이든 버스가 실제로 느려지거나 멈추거나 정류장을 건너뛰면 바로 드러납니다.

| 감지 | 판단 기준 | 추천에 반영 |
|---|---|---|
| 정지 | 한 구간에 평소보다 8분 이상 더 머묾 | 그 노선 이동시간에 지연 추가 |
| 정체 | 최근 구간을 평소의 1.8배 이상 걸려 통과 | 그 노선 이동시간에 지연 추가 |
| 건너뜀 | 2분 안에 정류장 순번이 3칸 이상 뛰며 후보 정류장을 지나침 | 그 정류장에서는 탈 수 없는 것으로 처리 |

- 평소 이동 시간은 수집 데이터 실측값(train.py 의 seg_min), 없으면 정류장 간 거리 ÷ 평균 속도로 추정합니다.
- **국가교통정보센터 돌발상황정보**로 노선이 지나는 길(정류장·경유지를 이은 선 400m 안)의 사고 · 통제 · 정체를
  원인과 함께 알려주고, 버스가 막히기 전에도 예상 지연(사고 12분, 전면 통제 15분, 정체 4분, 최대 15분)을 반영합니다.
  - 고속도로 돌발은 그 노선이 실제로 타는 고속도로(config 의 roads)만, 서울 방향만 반영합니다.
  - 차로 일부만 막는 공사는 지연으로 치지 않습니다. 앞차 기록으로 실제 지연이 확인되면 그 값이 우선합니다.
- 경로가 다른 노선(예: 경부고속도로의 8800·3007·3008 vs 의왕·과천의 7001)끼리 비교되므로, 한쪽 도로가 막히면 다른 쪽을 추천합니다.

## 실행 방법

```bash
pip install requests pandas scikit-learn joblib

# 1) 인증키 설정: api_key.example.py 를 복사해 api_key.py 로 만들고 키 입력
#    (공공데이터포털 · 경기데이터드림 · ODsay · TMAP 키)
# 2) 주변 정류장과 서울행 노선 찾기 → 결과를 config.py 에 입력
python find_nearby.py
python find_ids.py

# 3) 잔여 좌석 수집 (bus_seats.csv 에 저장, Ctrl+C 로 중지)
python collect.py

# 4) 평일 10일 이상 모은 뒤 모델 학습
python train.py

# 5) 정류장·노선 추천 (예: 월요일 07:30 집에서 출발)
python recommend.py 07:30 0

# 6) 지금 실시간 대안 안내 (기다리기 / 걸어가기 / 다른 버스)
python live_recommend.py

# 환승 경로·도보 시간만 따로 보기 / 키·IP 점검 (ODsay는 등록한 공인 IP에서만 작동)
python transit.py
python check_keys.py

# 돌발상황만 따로 보기 (collect.py 가 켜져 있어야 함)
python incidents.py

# 날짜 종류 · 지역행사만 따로 보기
python daytype.py 2026-10-05
python events.py

# 시연: 가상 상황 7가지 (만석 3가지 + 고속도로 사고 + 우회 + 공휴일 + 지역행사)
python demo_scenarios.py
```

## 자동 수집 (노트북을 켜 두지 않아도 됨)

GitHub Actions 가 **첫차 전 05:00부터 막차가 서울에 닿는 다음 날 01:30까지** 수집해
`data/bus_seats_운행일.csv` 로 저장소에 커밋합니다 (자정~03:00 기록은 전날 운행일 파일에).

- 운영계정(하루 10,000회) 승인으로 **하루 종일 1분 간격** 수집, 노선 운행 시간 밖에는 조회 안 함
- 하루 예상 호출 약 4,600회 (`python collect.py --estimate`) — 나머지는 실시간 추천·테스트용
- GitHub 실행은 한 번에 최대 6시간이라 **이어달리기**: 한 번에 340분 수집 후 저장하고 끝나면,
  매시간 예약돼 대기 중이던 다음 실행이 바로 이어받습니다.

1. 저장소 **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `SERVICE_KEY` / Secret: 공공데이터포털 인증키
2. **Actions 탭 → collect-bus-seats → Run workflow** (`quick_test` 체크) 로 연결 확인
3. 이후 자동 실행 · 노트북에서는 `git pull` 로 데이터를 받아 `python train.py`

## 파일 구성

| 파일 | 설명 |
|---|---|
| `config.py` | 후보 정류장(도보 시간), 노선별 정류장 순번, 수집 시간 등 설정 (하차 정류장은 자동 선택) |
| `find_ids.py` | 노선 ID와 정류장 순번 검색 도우미 |
| `find_nearby.py` | 기준 정류장 주변(반경 700m)의 정류장과 서울행 광역버스·정류장 순번 조회 |
| `collect.py` | 버스위치정보 API로 잔여 좌석을 1분마다 수집 |
| `.github/workflows/collect.yml` | GitHub Actions 자동 수집 (첫차~막차, 이어달리기) |
| `save_data.py` | 수집 결과를 운행일별 파일(data/)에 이어 붙임 |
| `train.py` | 노선 × 정류장별 탑승 성공 여부를 Random Forest로 학습·평가, 이동시간·배차 실측 |
| `recommend.py` | 출발 시각을 넣으면 정류장·노선 조합을 기대 도착 시각 순으로 추천 (출발 전 계획용) |
| `live_recommend.py` | 실시간 버스 위치·좌석으로 기다리기 / 걸어가기 / 다른 버스 중 추천 |
| `demo_scenarios.py` | 가상 상황 7가지(만석 · 고속도로 사고 · 우회 · 공휴일 · 지역행사)로 실시간 추천 시연 |
| `daytype.py` | 평일 / 토요일 / 일요일·공휴일, 출퇴근 시간대 판단 |
| `events.py` | 지역행사로 인한 승객 쏠림 · 정체 영향 계산 |

| `survey_form.gs` | 이용자 설문 구글폼 자동 생성 스크립트 (Google Apps Script) |

## 탑승 성공의 정의

좌석제 버스는 좌석이 남아 있는 한 줄 선 사람을 모두 태웁니다.
그래서 **각 후보 정류장을 떠난 직후 잔여 좌석이 1석 이상이면 "그 정류장에서 탑승 성공"** 으로 봅니다.
출발점(수원버스터미널)은 항상 좌석이 비어 있어 의미가 없기 때문에, 실제 탑승 정류장을 기준으로 측정합니다.
